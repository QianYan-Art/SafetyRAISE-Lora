# 报告实验第二版：MLP 方向权重编辑

2026-11-03 至 11-04 在 Orin 上完成。

本文的读者是想了解或复现“报告实验第二版”的人：为什么做、怎么做、结果如何、能说明什么、不能说明什么、下一步怎么走。逐项数字见 [`../eval/weight-edit-2026-11-04/`](../eval/weight-edit-2026-11-04/README.md)，脚本见 [`../harness/orin/wsp/`](../harness/orin/wsp/README.md)。

## 0. 一页纸

**做法。** 参考 weight-space-programming（rikiyat 的博文“实验 8”），在交付模型 v3h2 的合并权重上做 MLP 方向编辑。只动第 36–52 层的 `ffn_down`，每层加一个秩 1 的改动 ΔW = c·u·vᵀ（c = 0.278），然后重新量化为 Q4_K_M。其余张量与交付模型逐字节相同。MTP 头在编辑后的模型上重训过。

**效果。** 目标是让致因分析和责任分析抓住事故的核心机制。验收用开发集 12 案的续写探针，人工判读“是否把真实事故机制当作首要假设并写出因果过程”：

| 配置 | 抓到 / 部分 / 未抓到 |
| --- | --- |
| 交付模型 | 0 / 2 / 10 |
| 编辑后，原提示 | 4 / 6 / 2 |
| 编辑后，系统提示末尾追加“抓核心”要求（P2） | 9 / 2 / 1 |

各配置都没有编造数值，也没有越界定责。编辑后的模型与运行时控制向量 0.25 逐档等价。

**用法。** 运行时不需要控制向量或其他参数，服务配置与交付模型完全相同。想要最好的效果需要配 P2 提示，但这会改变线上协议，是否采用由仓库所有者决定。

**速度。** 与交付模型持平。新旧 MTP 头在同一正文上接受率相同，说明编辑没有让旧头失配。

**发布与存放。**
- Hugging Face `shiqianyan/SafetyRAISE-MainAgent-Exp` 公开了两个 GGUF：`report-exp-v1/` 是交付模型，`report-exp-v2/` 是本版。
- 编辑包（u、v）、两个 MTP 头和全精度权重都不公开，放在 Orin 上，仓库所有者本机有备份。

**方向判断。** 这次编辑只覆盖“提示能诱出”的那部分能力，主要撤销的是我们自己微调带来的过度保守写法。它不能说明解开了基座 agent 特化对能力的压制，见第 7 节。

## 1. 动机与假设

**为什么怀疑能力被压制。** Qwen3.8-27B 没有公开的纯预训练基座。它是在 Qwen3.5 架构的 27B 上做后训练得到的，出厂就是 coding/agent 特化的模型。仓库所有者最初的怀疑是：这种特化压住了模型本来会的长篇分析与报告写作能力，而 v3h2 的微调又让写法变得过度保守，致因和责任两节大量写成“X 已记载，不能认定 Y”。

**博文的启发。** 博文在 Qwen3.5-0.8B 上找到一个单一的“挡路行为”（循环），在残差流里取它的方向，把它从 `mlp.down_proj` 里投影掉，正确率因此大幅提升。博文也给了反例：在 Gemma 上，没有单一障碍的情况下编辑无效。也就是说，编辑只能移除障碍，不能凭空增加能力。

## 2. 阶段 0 / 0b：有没有可去除的障碍，能力是否潜藏

**阶段 0：没有可去除的循环。**
- v3h2 没有博文那种紧密死循环。真正的空转是“在思考里反复起草整份报告 2 到 4 遍，直到预算截断”。
- 不设思考预算重放 17 条，15 条自然结束。读各稿内容，改动主要是补字段，分析段在各稿之间基本不变。
- 结论：这是协议驱动的重写，不是文档级循环。去循环式的编辑价值低。

**阶段 0b：与官方 Qwen3.8-27B 对照。**
- 对照对象是官方 Qwen3.8-27B，它本身就是 agent 特化的后训练模型，不是纯基座。
- 同一提示下，官方模型的分析篇幅约是 v3h2 的 2.4 倍，否认措辞少，会提出竞争假设，但协议遵守差。
- 用“抓核心”粗评再看：官方模型并没有更抓核心，只是铺得更宽。照搬它的风格去取方向，会把铺陈也一起带回来。所以放弃“推断对否认”这个方向。

**P2 判别实验：能力潜藏。**
- 做法：原协议不变，只在系统提示末尾追加“抓核心”的分析要求（文本见 Hugging Face 仓库 `report-exp-v2/system_prompt_suffix_p2.txt`，或 `harness/orin/wsp/make_p2.py`）。它按因果分析模板改写：因果框架 → 核心机制 → 关键区分证据 → 必要性与常态性判断 → 结论翻转条件；与核心无关的背景不展开。
- 结果：v3h2 在 P2 下有核心框架句的比例约为 69%，原协议只有 0–10%。约一半案件写到位，没有编造，也没有越界。
- 判定：模型本来就会这样写，能被提示诱出。

## 3. 阶段 1：取方向与转向筛选

**取方向。**
- 配对数据：6 个开发案。A 取 P2 写法的第四、五节，B 取原协议写法的第四、五节。同一案件的两组共用原协议提示和同一份第一至三节前文。
- 在服务模型（Q4_K_M、KV q8_0）上取每层 l_out 在第四、五节区间的均值。
- 方向 u 取按案件平衡的 A−B 均值（`compute_dir.py`），写成控制向量。llama.cpp 的 `direction.il` 加在第 il 层 FFN 残差之后，与 `down_proj` 编辑的作用位置相同。

**筛选。** 用续写探针在层 36–52 上试不同强度：
- 随机方向 0.25 与基线无差别，说明起作用的是方向本身，不是扰动。
- 0.25 有真实但温和的改进。
- 0.35 开始出现条件式的责任权重。
- 0.50 过量，出现大量假设分支、自编阈值和与核心无关的竞争解释。
- 剂量窗口约在 0.25–0.3。

**完整协议确认。** P2 加向量对比只加 P2：竞争解释或翻转条件从 1/16 升到 9/19，没有编造，也没有越界。

## 4. 阶段 2：固化成权重

**困难与思路。** `down_proj` 没有偏置，不能直接加一个常数向量。做法是让 ΔW_l = c·u_l·v_lᵀ，并要求 v_l·a ≈ 1 对每个 token 都近似成立（a 是 `down_proj` 的输入，即 llama.cpp 里的 `ffn_swiglu-<il>`，长度 17408）。这样 ΔW_l·a ≈ c·u_l，近似于在该层输出上加了控制向量。

**选神经元。** 每层从拟合序列中选 512 个“稳定常开”的中间神经元（`edit_select.py`），排除汇聚位激活异常和长尾极值的神经元。

**求 v。** 只在这些神经元上做岭回归：v = (G + λ·tr(G)/k·I)⁻¹ s，λ = 0.01，再归一化使拟合集的平均增益为 1（`edit_solve.py`）。
- 拟合用 6 案，留出 3 案。
- 留出集增益均值 0.998，最差 0.988。
- 逐 token 的相对标准差约 14%。
- 汇聚位的最大增益 0.83。
- 改动幅度 |ΔW|/|W| ≈ 1.5%。

**写入。** 交付 Q4_K_M 的 17 个 `ffn_down` 先解量化，加 ΔW 后存成 F16，再用 `llama-quantize` 按 Q4_K_M 规则量化回去（`edit_build.py`、`edit_make.sh`）。不加 `--allow-requantize`，所以其余张量逐字节拷贝。

**数值核对。**
- 按 c = 0.25 写入时，编辑偏移只有控制向量的 0.83–0.91 倍，重量化吃掉了约 10%。
- 按 1/0.9 补偿到 c = 0.278 后，幅度为 0.94–1.02 倍，余弦 0.97–0.99。
- 零编辑（只做一遍重量化）的偏移约为控制向量的 4%，且与方向无关。

**要不要给编辑层提高量化精度：不需要。**
- 补偿之后，重量化带来的损失只剩几个百分点。
- 最终 GGUF 的行为与控制向量逐档对齐，见第 6 节。
- 把这 17 个张量升到 Q8_0，文件约多 0.7 GB，单路解码约慢 4%。
- 只有在行为验收明显变差时才值得做。

## 5. 阶段 3：MTP 头重训与速度

在控制向量的实验里，草稿接受率从 0.621 降到 0.557，因此在编辑后的模型上重训了 MTP 头。

**训练。**
- 特征来自真实服务环境：在编辑后的 Q4_K_M（KV q8_0、FA）上用 `dump_hidden` 导出隐藏状态（`mtp_feat_gguf.sh`）。
- 训练配方与 v3h2 的 MTP 头相同：官方头初始化，3 轮，60 条训练序列、10 条留出。
- 留出一致率从官方头的 0.893 / 0.816 / 0.755 升到 0.899 / 0.845 / 0.810。

**换头。** `mtp_splice.py` 只替换 GGUF 里的 MTP 块（blk.64.*），做法是临时 HF 目录加 `convert_hf_to_gguf.py --mtp`，再走 q8_0 → `llama-quantize --allow-requantize`，与交付流程的 BF16 → Q8_0 → Q4_K_M 一致。自检确认 15 个张量的名字、形状、类型都一致，其余张量不变。

**速度。**
- 在 Orin MAXN、补丁构建、单路下，贪心解码 5 案的正文逐字一致：v3h2 旧头 16.99 token/s，新头 17.02 token/s，接受的草稿 token 为 2351 对 2350。两个头完全持平。
- 采样（温度 1.0）下的测速会让正文分叉，噪声大，只能看量级：交付模型 12.59、编辑加旧头 13.00、编辑加新头 12.33 token/s。
- 结论：这么小的编辑不会让 MTP 头失配。之前看到的接受率下降，很可能来自采样噪声和运行时控制向量，没有单独验证。按仓库所有者的选择，最终 GGUF 融合新头，旧头留作对照。

## 7. 方向判断：这次编辑能说明什么、不能说明什么

**假设：agent 特化真的压制了报告能力。那么这次编辑没有解开那部分压制，原因有五条。**

1. **方向的上限就是 P2 提示能诱出的行为。** u 是从“同一模型加 P2”与“同一模型不加 P2”的对比里学出来的。所以它能做到的，最多是把“加了提示才会”变成“不加提示也会”。被特化压到提示也诱不出来的能力，这个方向里不包含。
2. **只学了报告段。** 方向只在第四、五节的 token 上取，拟合序列虽然包含思考，但方向本身没有区分“作为 agent 执行任务”和“作为分析者写报告”这两种模式。
3. **只有一个秩 1 方向。** 每层一个方向，表达不了更复杂的能力结构。
4. **做的是叠加，不是消融。** 编辑是往残差里推一个方向，而不是把某个抑制方向投影掉。即便存在一个“agent 模式”方向在压制分析能力，这次也没有去除它。
5. **对照对象本身就是特化模型。** 官方 Qwen3.8-27B 没有更抓核心，只是铺得更宽。所以这次撤掉的，主要是我们自己微调带来的含糊写法，而不是出厂特化的影响。

**仍然成立的结论。** 这类能力在 v3h2 里是潜藏的。一个很小的秩 1 编辑就能把它稳定地调出来，而且不破坏协议遵守，也不越界。

## 8. 下一步

**在 Qwen3.8 上，如果要检验“特化压制”这一假设。**

（1）构造隔离 agent 模式的对比对。

- 同一案件，分别给出有工具与无工具的设置，以及执行者与分析者两种框定。
- 方向要连同思考 token 一起取，而不只看报告段。

（2）对比消融与叠加。

- 把方向投影掉，比较 W' = W − c·u·(uᵀW) 与这次的加法有什么不同。
- 同样要配剂量、随机方向和层位三组对照。

（3）在服务用的量化模型上拟合，并重测 MTP 接受率。本次的经验是：编辑小的时候不需要重训头。

（4）在线上协议全流程上用开发 38 案做确认。测试 50 案不碰。

**换到 Qwen4-27B 新基座：微调 + 编辑权重两步走。**

Qwen4-27B 即将发布。这个体量的模型在当前环境下，出厂时大概率仍是 coding/agent 特化的，但它和 Qwen3.8 可以形成有价值的对照。以后有时间，可以按两步走来做报告模型：

- **第一步：微调。** 沿用本仓库的流水线：SFT 谱系、线上环境后训练、MTP 重训。目标是先拿到线上协议的遵守和事实义务。
- **第二步：编辑权重。** 在微调后的模型上，用 P2 式的同模型对比取方向，固化成 `down_proj` 编辑，用来恢复被微调压成保守写法的分析能力。

**对照的意义。** 第二步的增益在 Qwen4 上和在 Qwen3.8 上是否一致，可以帮助区分两件事：报告能力的上限由基座决定多少，被特化或微调压住了多少。

**第二步可以先用控制向量筛选。** 筛选的流程是控制向量 → 剂量窗口 → 固化 → 数值核对 → 续写探针验收，与本文第 3 至 6 节一致，可以直接复用 `harness/orin/wsp/` 的脚本。脚本里写死的层号、维度和张量名，要按新架构核对。
