# 交通事故报告模型训练策略：首版

日期：2026-09-30。目的不是复述事故，而是在给定人、车、路、环境与证据条件下，
写出事实可靠、因果边界清楚、引用可查、缺口明确的交通事故分析报告。
以下是后续训练的实验方案，不是已执行训练或“已证明最优”的结论。

## 先交付什么

SFT：1,698 条、534 个独立训练事故组，writer 1,398、reviewer 300。
writer 包括完整报告 534、长报告补充 139、分节 356、证据定位 150、
定向修订 69、脚本工具动作 150；后者不是真实模型工具轨迹。
输入总量 2,941,164 tokens，监督量 705,083 tokens。
开发与测试各 50 个独立事故组。

在线后训练：534 个完整报告任务及分包的 534 个奖励参考，与上述训练组重用，
不增加独立事故组。正式 DPO 偏好对和实际 rollout 均为 0。
本包不把主观评分、预置错误或参考报告改名为实际模型候选。

事故可以合成。接受标准是交通机制符合现实、数字和时序可自洽、结论能由可见证据支持，
而不是事故是否真实发生。参考报告只代表已接受写作目标，不代表现实事故真值或唯一正确答案。
NTSB 式“经过—调查事实—分析—原因与促成因素—安全建议”的组织方式可以学习，
但美国调查报告的 probable cause 不直接等于中国交通法律责任认定。

## 小模型优先补什么

以下为需要开发集验证的短板假设，不是本模型已经测得的诊断结果。

| 短板 | 首版数据与训练对策 | 训练后检查 |
|---|---|---|
| 长输入漏事实、串人物或车辆 | 完整报告与分节共享同案事实；监督事实与证据定位 | 关键事实召回、无依据新增事实、实体归属错误 |
| 时序与数字漂移 | 对照原始输入，训练有依据的定向修订；计算结果保留单位和条件 | 事件先后、速度/距离/时间关系、单位与派生量 |
| 把相关性或事后状态写成原因 | 完整报告学习因果链、替代解释及证据限制 | 主要原因、促成因素、损害扩大因素是否混淆 |
| 套话与总是要求补证 | 同时保留可下结论与确实不足的案例、正例审查与错误审查 | 有证据时敢于作有限结论，不足时不编造 |
| 法条适用和引用幻觉 | 后续接入固定法规/标志标线知识快照，训练检索后有依据写作 | 版本、地区、适用条件、正文定位与论证对应 |
| 自审漏报或过度否定 | reviewer 300 条学习具体定位与最小修订 | 漏报、误报、修订后是否引入新错误 |
| 格式与工具协议不稳 | 首版只保留明确标记的脚本动作监督；后续采集真实执行 | 工具调用可执行性和观察真实性另测，不由文本分数推断 |

首版主包法规引用任务为 0，所以不能以此包训练成功推定法规能力已补齐。
法规及标志标线宜保留在系统的版本化知识库中，通过检索供给模型；
SFT 学习怎样判断适用与引用，不要求把全部条文永久记进参数。
知识库内容交接见 `docs/kbase-content-adjustment-handoff.md`：
本轮未再次审计更新后的条目，不将训练包引用任务为 0 当作知识库缺内容的证据。

## 首轮：领域 SFT 与响应蒸馏

1. 锁定基座、tokenizer、模板、量化和数据哈希，保存未训练基线。
2. 先运行 16–32 条训练侧样本诊断，检查 loss mask、反向、保存/重载和长样本完整性。
3. 用全首版 SFT 起步，不叠加历史包或同批 messages 表示。
   先保存 0.5 与 1 epoch 检查点，由开发集选择，不为了收敛机械多训。
4. 优先 QLoRA/LoRA，不全参数训练。候选起点为 r=16、alpha=32、dropout=0.05、
   AdamW 学习率 1e-5、microbatch=1、累积约 8 条、梯度裁剪 1.0。
   参数是实验起点，不是本领域已验证最佳值。
5. 初轮不 packing；不截断报告末尾、事实卡或法规正文。超长样本分桶或使用适配上下文。
6. 保留 writer/reviewer 标签做分项统计；不能把 300 条审查意见自动当额外完整报告。

这里的响应蒸馏是使用获准且通过事实等硬门的优质教师最终输出做监督，
不请求隐藏思维链。现有合成目标可先训练；尚未执行的 MiniMax Flash 生成不算蒸馏成果。
首版冻结以后，教师重点补学生实际错误与薄弱场景，不继续无差别扩量。
教师同意不能替代事实、引用、隐私和泄漏检查。

固定 Qwen 文本资产为 `Qwen/Qwen3.8-27B` revision
`1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0`，资产清单
`profiles/assets/qwen3.8-official-1d4bf0f2/asset-manifest.json`。
其哈希为 `8b153def98f136293ce6bfc690c713ab917687404022c2b05ea8b7390d7477df`；
训练 profile 哈希为 `effa0fc602b0f8153fc8a640b81e7012bd61328450ef8a588e87e904e4ac0a1e`。
同族模型也不能假定 token ID 和模板相同；改基座时从 messages 重新导出。

## 后训练：GSPO 候选，DPO 对照

首轮不默认 PPO。报告属于长序列、开放式目标，奖励可靠性和采样成本通常先于算法选择。
采用以下顺序，始终保留更好的 SFT 检查点。

| 方法 | 本项目选择 | 必需输入与条件 |
|---|---|---|
| GSPO | 在线 RL 首选实验候选，不宣称一定胜过其他方法 | SFT 学生、同 prompt 多样本 rollout、冻结参考策略、经过校准的奖励实现、训练器支持 |
| DPO | 离线对照，学生候选可核查且采样较少时适合先做 | 同一可见输入/工具环境下的真实 chosen/rejected，逐对审查；不能用预置错误凑对 |
| PPO | 暂不作为首轮默认；确有价值模型、奖励与稳定实现再比较 | actor/参考策略、critic/value 训练、奖励与更充分的资源诊断 |
| GRPO | GSPO 训练器或后端不适配时的独立候选 | 同组 rollout 与奖励；更换算法需明确配置，不把 GRPO 日志写成 GSPO |

GSPO 原工作使用序列层面的重要性权重与组内优化，值得在本任务长报告上检验，
但论文结果不是本项目的领域效果证据。
开始时可用训练侧 64 个不同事故任务作端到端诊断，每 prompt 采样 4 个候选作为候选起点，
再扩大到全部 534 任务；仍不跨组泄漏，不因分数一致就接受。
GSPO clip、KL 系数、batch 与 rollout 长度必须按实际训练器语义和开发集确定，
不能直接照搬别的模型的数值。奖励全相等的组先定位奖励区分度或题目难度，
不伪造差分奖励。DPO 可另以 beta=0.1、学习率 1e-6、0.5–1 epoch 为实验起点。

本包 `rl-prompts.zip` 是通用 messages 任务格式，不冒充已适配某训练器的 Parquet。
训练接入时 actor 仅消费 `messages`；奖励进程按 task_id 从独立参考包加载材料。
若框架允许 ground_truth 字段，也不得渲染进 actor prompt。
重复使用训练事故是允许的，但必须按事故组抽样，不能把同案多个视图当独立案件。

## 奖励：硬门先于总分

奖励实现与裁判校准尚未执行，首版交付的是材料及合同。
一个可用的混合奖励应包含确定性检查和逐断言核验，不以词面相似、字数或多数投票判真。

- 硬门：无依据关键事实、事故身份或时序错置、数字结论冲突、伪造法条/证据/工具、
  泄露敏感信息或测试材料。触发任一项，不可被文笔或总分抵消。
- 非确定性重大判断无法确认时进入“需复核”，不能默认通过，也不能用缺失值当零风险。
- 质量分建议分解为事实与证据 40%、因果分析 25%、不确定性与替代解释 15%、
  任务覆盖 10%、表达与可读性 10%。权重需要在开发集校准。
- 没有给法条的任务不奖励编造法律引用，也不因没写法条扣分；有知识正文才核验引用。
- “无法确定”只在证据确实不足时得分；证据充足却回避结论不得高分。
- 效率仅在硬门通过、质量相当后比较；不以少写事实或硬截断输出获得效率奖励。

用含可接受改写、严重错误、轻微措辞差异的盲样例校准裁判。
发现裁判偏爱参考措辞、长答案或套话时，先修奖励，不用 RL 放大偏置。
合成错误可用于奖励校准，但仍不是学生实际 rejected 或正式 DPO 数据。

## OPD 与逐 Transformer 块调整

OPD 不是首版前置。标准 token 级 on-policy distillation 需要学生从当前策略采样，
并能在学生生成轨迹上获得教师 token 概率或等价可计算的蒸馏信号。
目前 MiniMax 适配器只采集最终正文，不提供本项目需要的教师 token log-prob，
因此无法宣称已具备教师 token-log-prob 驱动的 OPD。
标准 token 级 OPD 不要求完整词表 logits 或教师隐藏状态：
可在学生采样 token 上取得教师与学生 log-prob，再构造相应的蒸馏信号。
这与另做完整 logits、top-k 或中间特征蒸馏是不同条件。
学生错误驱动的教师改写再做 SFT 是可行的响应蒸馏，不应改名为上述 token 级 OPD。

当 SFT 有收益但仍在长因果链或罕见边界上失败，且有可访问 token 概率的合规教师，
再比较 SFT+OPD 与 SFT+GSPO。特征蒸馏另需教师隐藏状态、层对齐与可训练映射，
闭源正文 API 不具备这些条件。

可以覆盖每个语言 Transformer 块，但先采用各语言层 LoRA 的统一基线：

- 按真实模块清单选择注意力与 MLP，混合注意力不凭 `q_proj` 字符串猜接口。
- 基座冻结，视觉、投影与 MTP 等非本任务模块不默认纳入。
- 记录逐层梯度/更新量，做层或层组适配器禁用对照，以开发集识别敏感层。
- 有证据后比较逐层 r=8/16/32 分配与仅后 1/3 层适配；一次只改变一个因素。
- 直接解冻块、剪层、改注意力或量化内部状态是另立的架构实验，
  需要资源预算、等价性与能力回归，不能由这 1,698 条数据推定收益。

不为了“每一块都优化”而逐块堆改动。优先改善输入证据、监督和奖励；
结构改造不阻塞第一个可用模型。

## 评测与下一轮数据

开发集用于选配置与错误分析；测试集只在冻结候选时验收，
不反复看测试答案来补训练数据。量化校准只用训练侧。
按案件报告严重错误率、关键断言可支持率、数字与时序错误、引用适用性、
缺口识别、审查漏报/误报，以及时延与资源，不以单一均分替代重大错误门。
测试只有 50 组合成事故，不能代表真实生产分布。

第一轮必须对照：未训基座、SFT、SFT+DPO 或 SFT+GSPO。
若后训练没有改善，交付 SFT，不强制叠加算法。
下一轮只补错误簇、法规/标志标线有正文的检索任务、真实工具执行与需要长链推理的场景，
保持来源、同案分组和版本。完整真实事故许可/隐私闭环后再做独立外部验证，
不因合成能用而永久放弃现实评测。
