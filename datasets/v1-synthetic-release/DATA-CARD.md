## 来源与质量

SFT 原样继承已冻结 v22 档案，不把旧版、候选、隔离案例、私有原件或许可未确认材料混入。
事故是原创合成，不是现实事实；既有非作者审查与局部修订记录保留在原血缘中。
质量门不可由模型一致、长度或总分替代。

工程检查包括来源与成员哈希、三视图身份、RL 消息结构与参考绑定、
训练留出组及精确输入/目标隔离。没有对全库重新进行逐案语义复审，
哈希零重合也不能证明机制或模板无语义近邻。
参考报告不表示唯一正确措辞，不作为法律事实真值。
RL 的 `input_sha256` 绑定完整 system/user 消息的紧凑 JSON 加 LF，
源 `visible_input_sha256` 只绑定 user 正文；两者分别保存，不能当作同一种哈希。
编码细节见 `START-TRAINING.md`，完整参考正文子串检查不等于全面语义泄漏审计。

## 使用限制

- 仅本地训练用途，继承 `outbound_eligible=false`；不能据此上传云训练或外部裁判 API。
- SFT 的通用消息和 token 化表示是同一批数据，只选一种，不叠加。
- 原 token 化视图已做数据侧反解与 mask 检查，实际训练 collator、loss shift、
  反向与 packing 尚未验证。
- RL actor 不得读取奖励参考；奖励实现与裁判校准未执行。
- 法规及标志标线能力、真实工具行为和现实事故泛化尚不能由首版保证。
- 未训练模型、未测 SFT/RL 的效果；训练后应以开发集错误驱动下一版。

此前凭据曾进入工具回执，不能宣称整个历史过程“从未外发”；
本次导出不读取凭据或历史事故原件，不调用模型 API。
首版具体文件与来源哈希以 `manifest.json` 为准，验收范围见工作区发布报告。
